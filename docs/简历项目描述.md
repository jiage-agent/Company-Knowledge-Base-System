## 可直接粘贴的版本（推荐 4 条）

**企业知识库问答系统（Agentic RAG + 混合检索 + 权限隔离）**　个人独立项目
技术栈：Python 3.13 · FastAPI · LangGraph · ChromaDB · SQLite · BM25 + RRF · Cross-Encoder 重排 · DeepSeek · 阿里云 text-embedding-v4 · LangSmith
GitHub：github.com/jiage-agent/Company-Knowledge-Base-System

解决的问题：企业文档问答有三大痛点——检索召回不准、答案无法追溯、不同权限的人不能看到彼此的数据。用 Agentic RAG 把"检索"做成可自适应决策的多轮过程，让员工用自然语言查询内部文档，答案带可验证的引用，且**查不到就明确拒答、绝不编造**。

- **Agentic 编排**：基于 LangGraph 实现 7 节点状态图（查询理解 → 检索规划 → 混合检索 → 重排 → 生成 → Critic 校验 → 条件路由），支持意图驱动的策略选择（单跳/多查询分解/不检索）与证据不足自动改写查询重检索（上限 2 轮 + 图递归上限兜底）；闲聊与超纲问题走受限兜底、不调用通用大模型自由生成，规避合规风险。
- **混合检索链路**：稠密（向量）‖ 稀疏（BM25，中文按字+二元组分词）双路并行召回 → RRF 融合（只用名次、免疫量纲差异）→ 权限条件**下推**至向量库 → Cross-Encoder 精排（仅对 Top-30）→ 相关性阈值过滤 → MMR 去冗余 → 父块回填。自建 19 条多类型评测集做消融实验：Recall@5 0.882→**0.908**、HitRate@5 0.895→**0.947**、NDCG@5 0.831→**0.859**，代价是延迟 250ms→1115ms。
- **权限感知检索**：租户/部门/密级/角色白名单四元组，权限字段冗余至每个 chunk 并下推到向量库过滤（避免"先取回再过滤"导致的召回塌缩与越权风险），叠加应用层兜底校验与父块回访校验；实测同租户下研发账号（密级2）查询财务文档（密级3）被正确拦截并拒答，财务账号正常作答。
- **幻觉控制与工程化**：Critic 三重校验（引用真实性规则 + 答案数字与证据一致性规则 + LLM 判定，规则先行以省成本），实测 3 道超纲题中 2 道实现"零召回 + 明确拒答"；父子块索引（子块 240 字召回、父块 900 字生成）配合句边界对齐重叠，解决"切太碎丢上下文、切太大召回不准"；向量库/Embedding/重排/LLM 四层抽象支持改配置热切换（Chroma→Milvus、云端→本地模型），配套 Dockerfile + Compose、幂等去重入库、索引重建与端到端冒烟测试脚本。

**企业知识库问答系统（Agentic RAG + 混合检索 + 权限隔离）**　个人独立项目

- **Agentic 编排**：LangGraph 7 节点状态图（查询理解/检索规划/混合检索/重排/生成/Critic/条件路由），意图驱动策略选择 + 证据不足自动改写重检索（上限 2 轮），闲聊超纲走受限兜底不自由生成。

- **权限与幻觉控制**：租户/部门/密级/角色四元组，权限条件下推向量库 + 应用层兜底（实测研发账号查财务文档被拦截拒答）；Critic 引用真实性 + 数字一致性双重规则校验，超纲问题实现零召回明确拒答。

## 面试官最可能追问的 5 个点（提前准备）

1. **"混合检索提升只有 2.6 个百分点，值得吗？"**
   → 值得，但要说清代价：延迟涨了 865ms。提升幅度受"天花板效应"限制（19 条里 11 条在仅向量时已 NDCG=1.0）。重排更大的价值在"候选池大、噪声多"的真实场景，以及**拒答能力**（3 道超纲题的零召回数从 1/3 提升到 2/3）。如果业务对延迟敏感，可以只保留 RRF 融合、关掉重排（我有 `RERANK_ENABLED` 开关）。

2. **"为什么不用 RAGAS / Milvus / PostgreSQL？"**
   → 诚实答：当前版本用自建评测脚本（Recall/MRR/NDCG/HitRate 都是手写实现，可控且零成本）、ChromaDB、SQLite。不用 RAGAS 是因为我要的是**检索指标**（RAGAS 偏生成质量），而且自建能让我完全掌控评测口径。
   三者都做了抽象层与明确升级路径：向量库换 Milvus 只需新增一个适配器（接口已定义，`milvus_store.py` 里有完整迁移步骤），数据库换 PostgreSQL 只改一行连接串。**"什么时候该升级"比"用了什么"更重要** —— 我写清了触发条件（多 worker 部署、百万级向量、需要原生稀疏向量）。

3. **"权限隔离具体怎么做的？会不会漏？"**
   → 见手册 Q8/Q10：四道防线（入库带权限、检索下推、返回前兜底、父块回访校验）。还可以补一句：跨租户访问返回 404 而不是 403，避免泄漏 id 是否存在。

4. **"评测集才 19 条，结论可信吗？"**
   → 主动承认局限：统计置信度有限，应扩到 150~300 条并人工校验标注；目前 gold 用关键词反查索引，`gold_count` 从 0 到 4 不等，说明标注粒度还不够统一。**这是下一步要做的事，不是我不知道的问题。**

5. **"这个项目最难的/你踩过什么坑？"**
   → 讲三个坑（详见面试手册）：统一相关性阈值把 RRF 档指标打到 0.158（分数量纲不可比）；HyDE 让模型编出原文没有的数字、污染检索（主动放弃）；标题正则太宽把正文判成标题导致条款被静默丢弃。**能讲出踩坑和修正过程，比讲功能更有说服力。**
