# 现场演示手册（面试用）

> 目标：**3~5 分钟讲清楚"它能干什么、凭什么可信"**，不需要跑代码也能讲完。

---

## 零、演示前 2 分钟：一条命令自检

```powershell
cd "D:\develop\Company-Knowledge-Base-System"
.venv\Scripts\python.exe scripts\preflight.py
```

看到最后一行 **`[OK] READY FOR DEMO`** 就说明可以开始了。

**这个脚本会检查 5 件事**（任何一项挂了都会打印出来）：
1. 服务是否在跑（不在会自动拉起）
2. 预热：向量化 / 重排 / 检索链路（避免首个提问等 30 秒）
3. 三个演示账号能否登录
4. **权限隔离是否生效**（张三看不到财务文档、李四能看到）
5. 四类问题是否按预期回答

> ⚠️ 如果服务已经开着，**不要再跑任何 scripts 下的脚本**（会锁 SQLite 数据库）。
> 演示期间只通过浏览器/API 访问，不动脚本。

## 一、演示入口

**只开一个就行**：http://127.0.0.1:8000/docs

演示账号（租户统一填 `acme`）：

| 账号 | 密码 | 角色 | 部门 | 密级 | 能看什么 |
|---|---|---|---|---|---|
| `admin` | `admin123` | 管理员 | it | 4 | 全部 309 篇 |
| `zhangsan` | `pass1234` | 成员 | rd | 2 | 2 篇（看不到财务） |
| `lisi` | `pass1234` | 成员 | finance | 3 | 2 篇（含财务） |

**Swagger 操作路径**：
1. `POST /api/v1/auth/login` → 填 tenant/username/password → Execute → 复制 `access_token`
2. 点右上角 **Authorize** → 粘贴 token → Authorize
3. 之后所有接口都能直接调了

## 二、4 步演示流程（每步都有"讲什么"）

### 第 1 步：看服务自检（30 秒）—— 建立"这不是玩具"的印象

```
GET  /ready
GET  /api/v1/admin/health/components
```

**讲**：
> "先看依赖自检。这个项目现在是**全本地链路**：向量模型是 Ollama 跑的 bge-m3，
> 重排是本地 bge-reranker-base 跑在 RTX 4060 上，向量库 Chroma、元数据 SQLite。
> **整条 RAG 链路零云依赖、可以完全离线跑**，只有最后生成答案调 DeepSeek。
>
> 我特意把每个依赖的耗时都暴露出来，因为 RAG 系统最常见的故障是'某个外部服务挂了'，
> 而不是代码逻辑错。这张表能让排障从'猜'变成'看'。"

**预期看到**：5 个组件全部 OK，embedding ~80ms、rerank device=cuda。

---

### 第 2 步：权限隔离（90 秒）—— **最有说服力的一步，重点讲**

```
GET /api/v1/documents          （分别用 zhangsan 和 lisi 的 token）
```

**讲**：
> "这是我觉得企业场景最关键的一块。同一个知识库，不同权限的人看到的范围不一样。
>
> 张三（研发，密级 2）只能看到 2 篇；李四（财务，密级 3）能看到 2 篇但**其中一篇是财务的**。
> 这里有个设计要点：**权限条件必须下推到检索层**，不能先查出来再过滤——
> 那样会有两个问题：一是候选被过滤掉导致召回塌缩，二是**无权限的内容已经进了内存**，
> 任何一处日志打印都算泄漏。
>
> 我实现的是四元组：租户 + 部门 + 密级 + 角色白名单，
> 并且在向量库和 SQL 两边都下推，最后再加一层应用层兜底校验——不信任单点。"

**可以顺手展示的实测结论**（不用跑，直接说）：
> "我自己测过一个典型场景：张三问'50 万元以上的费用谁审批'，
> 因为那条规定在财务文档里（密级 3），系统**明确拒答**，不会编；
> 李四问同样的问题，正常答出'由总经理审批'并带上引用。"

---

### 第 3 步：完整问答 + 引用（90 秒）—— 展示"答案可追溯"

```
POST /api/v1/chat/ask
{
  "question": "一线城市出差住宿标准是多少钱？",
  "use_agent": true,
  "top_k": 5
}
```

**讲**（边指返回体边说）：
> "看返回结构，这里有几层信息：
>
> ① **答案带引用锚点** `[1]`，对应 citations 里的文档名、页码、相关度分数——可点击回原文。
> ② **运行轨迹**：intent=factual、strategy=single、retrieval_rounds=1、critic_passed=true。
>    这是我特意暴露出来的，因为 Agentic RAG 最容易变成黑盒——出了问题要能知道
>    **是哪一步错了**：是没检索到，还是检索到了但生成跑偏。
> ③ **置信度**：由检索分数、引用规范性、数字一致性加权算出来的。
>
> 延迟大约 2 秒，其中大头是 Ollama 向量化（~500ms）+ 重排（GPU 69ms）+ DeepSeek 生成。"

---

### 第 4 步：拒答能力（60 秒）—— **差异化亮点**

```
POST /api/v1/chat/ask
{ "question": "帮我写一首关于春天的诗", "use_agent": true }
```

**讲**：
> "企业知识库最怕的不是答不出来，而是**一本正经地编**。
>
> 这个问题知识库里没有，系统的行为是：意图识别为闲聊/超纲 → 走受限兜底话术，
> **不调用通用大模型自由生成**，因为内网场景下让模型自由发挥是合规事故。
>
> 我还做了双重的拒答保障：
> 一是**相关性阈值**——我用评测集的两组分数分布标定过，
> 重排分数能把'有答案'和'无答案'两类分开（阈值 0.115，分开准确率 100%）；
> 二是 **Critic 三重校验**——引用编号必须真实存在、答案里的数字必须能在证据原文匹配到，
> 最后才让模型判断语义层面是否被支持。**规则能拦住的就不交给模型，既省钱又确定。**"

## 三、如果面试官问"效果怎么量化"（不用跑，看 README）

打开 README 的「三、实测效果」，指这张表：

| 配置 | Recall@5 | MRR | NDCG@5 | 延迟 |
|---|---|---|---|---|
| 仅向量检索 | 0.5500 | 0.3254 | 0.3811 | 151ms |
| + BM25 + RRF | 0.5500 | **0.4279** | **0.4585** | 276ms |
| + 本地 Cross-Encoder 重排 | **0.6250** | **0.5667** | **0.5815** | 913ms |

**讲**：
> "评测集是我自建的两套：40 道从语料自动生成的可验证题（特征串唯一确定 gold 块），
> 75 道手写题覆盖事实/编号/同义/对比/多跳/拒答/权限七类。
>
> 这三行里最有意思的是**第二行**：Recall 没变，但 **MRR 提升了 31%**。
> 原因是我这份语料里有 300 多篇结构几乎相同的文档，靠编号前缀区分
> （`RD-APPEAL-` vs `FL-` vs `SR-`）。向量检索分不清这种纯编码差异，
> **BM25 靠精确字面匹配把前缀吻合的那条顶上来** —— 这就是混合检索不可替代的场景。
>
> 第三行是重排：Recall 再涨 7.5 个点，代价是延迟从 276ms 到 913ms。
> 我认为这个交换是划算的，但如果业务对延迟极度敏感，可以直接关掉重排（有开关）。"

**如果被追问"评测集才 40 条，可信吗"**：
> "不够。统计置信度有限，正确做法是扩到 200 条以上并人工复核 gold。
> 我踩过这个坑：最初用'关键词命中所有块'当 gold，结果 48/75 题三档配置全部满分、
> 毫无区分度——因为 gold 集合混进了不是答案的块。
> 后来改成'关键词筛候选 + 语义相似度选唯一源块'，指标才有意义。
> **指标不可信的时候，调优就是瞎调。**"

## 四、兜底预案（现场出问题怎么办）

| 症状 | 原因 | 当场怎么处理 |
|---|---|---|
| 首个提问等了 30 秒 | 模型冷启动 | 已加启动预热；如果还是慢，先说"这个回答同时在加载本地模型，我换个已经热的问题" |
| 提问返回"未找到可靠依据" | Ollama 或重排没起来 | 打开 `/api/v1/admin/health/components` 给面试官看，说明"某个依赖降级了"，然后重启服务 |
| 服务起不来 | 8000 端口占用 / Python 进程残留 | `Get-Process python \| Stop-Process -Force` 后重启 |
| DeepSeek 超时 | 网络问题 | 说"生成模型走的是云端 API，网络抖动；检索和重排都是本地的" |
| 完全没法演示 | 环境彻底坏了 | **直接讲 README 和架构图**，不看代码。面试官更在意你能不能讲清设计取舍 |

**最坏情况的说法**：
> "演示环境有几个外部依赖（本地模型服务、生成模型 API），我不想在这里浪费时间。
> 我可以直接讲设计：这个系统最关键的三块是 Agentic 编排、权限下推、Critic 校验，
> 每一块我都有实测数据支撑。您想先听哪一块？"

## 五、只给 HR 看 README 的话术（1 分钟）

如果面试官不要求跑代码，直接把 README 打开，按这个顺序指：

> "README 我按'能验证'来写的，结构是：
>
> **① 快速开始**——一条命令能跑起来（前置只要装 Ollama 拉个模型）。
>
> **② 架构与设计决策表**——这部分我写得比较用心：每一个技术选择都配了'为什么'和'代价'。
> 比如父子块索引解决了召回精度与上下文完整性的矛盾，代价是多存一份文本；
> 重排提升精度，代价是 +600ms 延迟。**我不写'用了什么'，只写'为什么用、代价是什么'。**
>
> **③ 实测效果**——三组消融实验的数字，全部可复现，脚本在 scripts 下。
> 而且我专门做了一个'证伪'实验：验证 BM25 到底贡献多少。
> 结论是换个 embedding 模型后，它的价值从'几乎为零'变成了'MRR +31%'——
> **这说明混合检索的收益不是常数，取决于语料特征和模型**。
>
> **④ 诚实的局限**——最后我列了 5 条已知问题，包括评测集规模不够、
> 本地重排在同质语料上分数不可分。我觉得**能说清自己系统哪里不行，比堆功能更有说服力**。"
